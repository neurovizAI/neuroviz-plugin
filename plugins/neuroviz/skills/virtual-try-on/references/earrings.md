# Earrings Try On — Agent Guide

_One-line: reach for this app when the user wants earrings from a product photo shown worn on a model's ear — with the model either generated by the app or supplied as a reference photo._

## What it does — and what it will NOT do

**Does:** Extracts the earrings (single or pair) from a product photo — any background works — sizes them, and places them on a model's ear. The model can be generated (steerable via `gender` and `user_instructions`) or guided by a `model_input` reference photo; a supplied reference produces a person who *resembles* the model, not the identical image — that resemblance-based re-render is required for correct jewelry placement. Framing is controlled by `is_closeup` (ear-area crop vs wider shot) and `is_lifestyle` (lifestyle environment vs white studio background). Output up to 16 Mpx native via `model_tier`, one result per run.

**Will NOT do:**
- Retouch, polish, remove scratches, or enhance the earrings — they are placed exactly as they appear in the photo.
- Change the design — metal, stones, shape, size of the piece itself.
- Handle other jewelry types (rings, necklaces, bracelets, watches) or several jewelry types in one run.
- Reproduce a supplied model photo pixel-for-pixel.

## Choose it / don't choose it (name the better app for each "don't")

Choose it for: e-commerce listings, social posts, and lookbooks showing earrings in context; high-volume catalogs where quick on-model shots are needed across many styles.

- Rings → **Rings Try On**. Necklaces/pendants → **Necklace Try - On**. Bracelets/bangles → **Bracelet Try-ON**. Watches → **Watch Try-On**.
- Several jewelry types worn together in one image → **Jewelry Set Try-On**.
- Retouching or quality enhancement first → **Jewelry Retoucher Precision** (faithful), **Jewelry Retoucher Vivid** (richer look), or **Jewelry Retoucher Rescue** (rough/worn source) — then come back here with the retouched image URL.
- Design changes (swap metal, change stones) → **Jewelry Modifier Pro** first, then the try-on.
- Exact manual control of earring size and position in the frame → **Earrings Try-On Studio**, where the piece is sized and positioned explicitly before generating.
- Styled scene around the earrings without a person → **Creative Jewelry Photographer Vivid**.

## Inputs that make or break the result

- `jewelry_photo_1` (required): a clean product shot of the earrings, ideally on a plain background. The **decorative front** must be visible — a photo showing only the post or clip mechanism cannot be placed. A front-facing view beats a steep angle; multiple angles of the same earring in one image help the 3D shape read.
- **Crop tight before hosting.** If the earrings are small in the frame with lots of empty background, crop closer and pass the cropped image's URL. Note: with `aspect_ratio` left at `"auto"`, the crop's aspect ratio becomes the generated image's aspect ratio.
- Sharpness and lighting: a soft photo loses fine detail in the result; a truly blurry one is unusable; uneven lighting shifts metal tone and color — even, diffuse, neutral light keeps them true.
- Prefer a product shot over a worn shot: earrings photographed on a person can sometimes be extracted, but results vary.
- `model_input` (optional): a reference without earrings already in the ears works best — existing earrings interfere with placement. Omit it entirely to have the model generated.
- `earring_type` and `product_size` are required and drive placement and scale — see the playbook.
- All image parameters take a publicly reachable HTTPS URL as a plain string.

## Parameter playbook

Exact names and enum values (schema is authoritative):

- `jewelry_photo_1` (image_url, **required**)
- `earring_type` (string, **required**, default `"Select Earrings Type"` — a placeholder, always replace it): `"Select Earrings Type"`, `"Stud Earrings"`, `"Hoop Earrings"`, `"Drop Earrings"`, `"Dangle Earrings"`, `"Chandelier Earrings"`, `"Climber Earrings"`, `"Threader Earrings"`, `"Teardrop Earrings"`, `"Cluster Earrings"`, `"Button Earrings"`, `"Huggie Earrings"`, `"Cuff Earrings"`
- `product_size` (string, **required**, default `"M (Medium)"`): `"XS (Extra Small)"`, `"S (Small)"`, `"M (Medium)"`, `"L (Large)"`, `"XL (Extra Large)"`
- `model_input` (image_url, optional) — omit to generate the model
- `gender` (string, default `"female"`): `"female"`, `"male"`
- `is_closeup` (boolean, default true) — true focuses on the ear area; false shows more of the model. Set it explicitly and keep it consistent with the model reference and instructions.
- `is_lifestyle` (boolean, default true) — true: lifestyle environment; false: white studio background.
- `user_instructions` (string, multiline, any language, optional, default `""`) — describe the model or environment when generating dynamically.
- `model_tier` (string, default `"ViTryon SD - 1Mpx"`): `"ViTryon SD - 1Mpx"`, `"ViTryon PRO (HQ) - 4Mpx"`, `"ViTryon PRO (HQ) - 16Mpx"`. SD ≈ 1024x1024; HQ 4Mpx ≈ 2000x2000; HQ 16Mpx ≈ 4000x4000 native (no upscale), with more precise rendering on the HQ tiers.
- `aspect_ratio` (string, default `"auto"`): `"auto"`, `"21:9"`, `"16:9"`, `"3:2"`, `"4:3"`, `"5:4"`, `"1:1"`, `"4:5"`, `"3:4"`, `"2:3"`, `"9:16"`. `"auto"` matches the earring image's crop.
- `quality` (integer, 50–100, default 80) — keep ≥70; 80–90 recommended
- `dpi` (integer, 72–300, default 300) — 300 is print standard; never below 72
- `extension` (string, default `"png"`): `"png"`, `"jpg"`, `"webp"`
- `lossless_webp` (string, default `"true"`): `"false"`, `"true"`

## Common failures -> cause -> fix

- **Input isn't earrings** -> ring/necklace/bracelet/watch or non-jewelry image passed -> route to **Rings Try On**, **Necklace Try - On**, **Bracelet Try-ON**, or **Watch Try-On**; several types together → **Jewelry Set Try-On**; otherwise provide a clear earrings product photo.
- **Earrings look dull, scratched, or unpolished in the result** -> this app places them exactly as photographed, it never retouches -> run a retoucher first (**Jewelry Retoucher Precision** / **Jewelry Retoucher Vivid** / **Jewelry Retoucher Rescue**), then pass the retouched URL here.
- **Asked to change metal/stones/design** -> not supported -> **Jewelry Modifier Pro** first, then the try-on.
- **Placement fails or looks wrong from the source** -> only the post/clip back is visible -> provide a photo showing the decorative front of the earring.
- **Fine detail lost** -> earrings small in frame or the photo is soft -> crop closer before hosting and/or provide a sharper, higher-resolution image; a very blurry photo will not produce usable results.
- **Metal tone or color shifted** -> uneven or colored lighting in the source -> use an evenly, diffusely lit photo with neutral light; state the true metal color in `user_instructions` if needed.
- **Dangle/drop earrings positioned like studs, or otherwise mis-hung** -> `earring_type` left at the `"Select Earrings Type"` placeholder, or a type that doesn't match the photo -> set the enum value that actually matches the earrings.
- **Earrings too large or too small on the ear** -> size control mismatch -> adjust `product_size` (XS–XL) and re-run; make sure `user_instructions` don't contradict the size choice (e.g. instructions saying "tiny studs" with `"XL (Extra Large)"` selected). For exact proportions, show the whole piece straight-on without heavy cropping or extreme perspective; if the selector still can't nail it, use **Earrings Try-On Studio** for manual size and position control.
- **Result shows a ghost of the model's own earrings or odd placement** -> the model reference already wears earrings -> provide a reference without earrings, or omit `model_input` and generate the model.
- **Result framing doesn't match the model reference or the instructions** -> `is_closeup` conflicts with the inputs: a wide reference or wide-shot instructions with `is_closeup: true` crops to the ear; an ear close-up reference or ear-focused instructions with `is_closeup: false` generates more of the model instead of matching the reference -> align `is_closeup` with the reference framing and the instructions.
- **Result is not the same person as the reference** -> by design: the generated person only resembles the supplied model; this is necessary for correct jewelry placement -> set that expectation with the user.
- **Pixelated or low-resolution output** -> `quality` set very low or `dpi` set very low -> use `quality` ≥ 70 (80–90 recommended) and `dpi` ≥ 72 (300 for print).
- **Specks on the earrings rendered as extra stones** -> dust/debris in the product shot read as detail -> clean the piece and re-shoot, or note in `user_instructions` that the specks are dirt.
